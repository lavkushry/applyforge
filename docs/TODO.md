# ApplyForge Roadmap & Outstanding Tasks

This document catalogues the remaining technical debt, architectural improvements, and feature expansions required to move ApplyForge from a robust MVP to a hardened production platform.

## Infrastructure & Platform Hardening

- [ ] **Alembic Database Migrations:** Fully transition away from the development-only `Base.metadata.create_all()` logic in FastAPI startup. Author complete Alembic revision histories to handle safe, forward-moving database schema evolution in production.
- [ ] **Remote Blob Storage:** Replace local disk mounts (`STORAGE_PATH` and `ARTIFACTS_PATH`) with an S3-compatible adapter interface. Support secure, pre-signed URL generation for downloading user resumes and viewing worker screenshots.
- [ ] **Real-time Event Streaming:** Upgrade the web frontend from interval polling to WebSockets or Server-Sent Events (SSE) to provide instant feedback during long-running Playwright application executions.

## Security & Access Control

- [ ] **Token Rotation:** Overhaul the simple JWT cookie architecture to implement proper short-lived access tokens paired with secure refresh-token rotation.
- [ ] **Role-Based Access Control (RBAC):** Introduce authorization middleware on API routes to support future Enterprise/Agency tiers (e.g., Coaches managing multiple candidate profiles).
- [ ] **At-Rest Encryption for Sensitive Data:** Ensure deeply personal user configurations and specific automation answers are encrypted at rest in the database, rather than stored as plaintext JSON blobs.
- [ ] **Aggressive Rate Limiting:** Expand current authentication rate limits to aggressively throttle resource-intensive endpoints, particularly LLM tailoring requests and active worker dispatches.

## Resume Engine Enhancements

- [ ] **Multi-Strategy Support:** Enable the creation of multiple distinct "Master Profiles" or core strategy branches (e.g., one tailored for Frontend Engineering, one for Product Management) linked to specific Role Strategies.
- [ ] **Rich Text Editing:** Upgrade the profile editor in the web application from basic text areas to a structured rich-text component, while maintaining clean Markdown/JSON data boundaries under the hood.
- [ ] **Advanced Rendering Options:** Expand the built-in theme library and provide deeper support for complex LaTeX and Typst rendering environments, ensuring strict fallback validation to guarantee ATS readability.

## Scraping & Company Intelligence

- [ ] **Direct ATS Extraction Models:** Build specialized, robust scraper models for prominent ATS portals (e.g., Greenhouse, Lever, Workday) to bypass generic board aggregators and ingest pristine, highly-structured job data directly.
- [ ] **Scraper Observability:** Implement a dedicated administrative UI tracking source-health metrics, scrape failure rates, and alerting for stale or broken company portals.
- [ ] **Company Record Merging:** Develop tooling for operators or users to manually merge duplicate company records generated by slight variations in scraped employer names.

## Worker & Automation Expansion

- [ ] **Extended Field Adapters:** Build specific automation adapters for complex UI patterns, such as multi-part address inputs, dynamic work-history tables, and proprietary date-pickers.
- [ ] **Checkpoint Resumption:** Enhance the FSM to support deep run resumption—allowing a worker that crashed halfway through a 5-page application to spin back up exactly where it failed without restarting the form.
- [ ] **Fallback Navigational Strategies:** Implement intelligent heuristic retries in the Playwright worker for locating submit buttons or next-page links when standard DOM selectors fail.

## Inbox Integration Polish

- [ ] **End-to-End Live Verification:** Complete comprehensive testing of the Outlook and Gmail OAuth flows against live, non-sandboxed provider accounts.
- [ ] **Automated Re-authorization Flows:** Build UI prompts instructing users to re-authenticate when provider refresh tokens expire or are revoked remotely.
- [ ] **Invalid Grant Handling:** Ensure the backend gracefully traps OAuth disconnects and logs an actionable diagnostic event rather than throwing a raw 500 error during OTP retrieval.

## Quality Assurance & Testing

- [ ] **End-to-End Testing (Playwright):** Establish a dedicated E2E test suite running against the Web UI to validate core user journeys: Sign-up, Profile editing, Scrape initiation, and PDF Export.
- [ ] **Integration Test Suite:** Expand backend coverage to explicitly test the interaction between the FastAPI endpoints and the local database state, moving beyond mocked unit tests.
- [ ] **Continuous Integration (CI):** Configure GitHub Actions (or equivalent) to automatically run Python test suites, enforce web type-checking, and validate Docker builds on every Pull Request.
