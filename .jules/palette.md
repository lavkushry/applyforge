## 2024-06-10 - Form Accessibility Bindings Pattern
**Learning:** Found a recurring pattern across form components (`auth-form.tsx`, `job-create-form.tsx`, `role-create-form.tsx`) where inputs lack strict `htmlFor`/`id` bindings with their labels, lack proper `type` attributes (e.g., `type="email"` for email inputs), and miss `aria-describedby` links to validation errors with `role="alert"`. This breaks screen reader experiences and click-to-focus for labels.
**Action:** Always utilize `useId()` inside form components to generate unique IDs, explicitly bind `<label htmlFor={id}>` to `<input id={id}>`, and connect validation errors using `aria-invalid` and `aria-describedby` referencing the error element's ID. Ensure correct semantic HTML input types and `autoComplete` attributes are used for standard fields like email and password.
