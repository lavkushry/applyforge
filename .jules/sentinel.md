## 2026-06-01 - Fix path traversal vulnerability in file uploads
**Vulnerability:** In `apps/api/app/services/files.py`, `Path(filename).name` was used on unsanitized user input (`filename`) in `save_upload`. On POSIX systems, `pathlib.Path` does not consider the backslash (`\`) to be a directory separator. A malicious user could provide a filename like `..\..\..\etc\passwd` or `..\..\..\tmp\malicious.sh` and it would be interpreted as a single valid filename on POSIX systems, but potentially lead to unexpected behavior or path traversal if later used in contexts or passed to systems that do interpret backslashes. More critically, when building the target path `Path(settings.storage_path) / f"{uuid4()}_{safe_name}"`, if `safe_name` contained path traversal sequences like `../` it could write outside the intended directory.
**Learning:** `Path(filename).name` alone does not adequately prevent path traversal on POSIX systems if the filename contains backslashes, because the backslashes are not stripped and are instead treated as valid filename characters.
**Prevention:** Always manually normalize backslashes to forward slashes (e.g., `filename.replace("\\", "/")`) before passing user-uploaded filenames to `pathlib.Path` for parsing.
