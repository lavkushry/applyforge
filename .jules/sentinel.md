## 2024-10-25 - Prevent Path Traversal in File Uploads
**Vulnerability:** The file upload handler `save_upload` in `apps/api/app/services/files.py` relied solely on `Path(filename).name` to sanitize the user-provided filename. On Unix systems, this does not correctly strip `\` characters (since they are treated as regular characters, not directory separators). A malicious user could supply a filename like `..\..\etc\passwd` which bypasses the `Path().name` check entirely, or directly supply paths like `../../etc/passwd` which, while handled by `Path().name`, still leave edge cases and unwhitelisted characters open for exploitation.
**Learning:** `Path(filename).name` is OS-dependent and insufficient for sanitizing untrusted inputs. It fails cross-platform directory traversal attempts (e.g. backslashes on Linux). Furthermore, not stripping dotfiles (`.`) or non-alphanumeric characters can result in hidden file creation or weird file system artifacts.
**Prevention:** Always implement a dedicated, cross-platform `secure_filename` function that explicitly replaces both `\` and `/`, strips leading dots, and enforces an alphanumeric whitelist (with hyphens/underscores/dots) on untrusted filenames.
