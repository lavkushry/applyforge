## 2026-06-23 - Consolidate Multiple Count/Exists Database Queries into a Single Round-Trip via scalar_subquery
**Learning:** Dashboard-style summary endpoints that collect counts or existences of related records using separate independent `.first()`, `.count()`, or `.exists()` ORM calls can suffer from unnecessary database round-trips. Grouping these aggregates and exist checks into individual `scalar_subquery` calls and passing them directly into a top-level unified `select()` call significantly improves throughput (e.g., from ~0.37s to ~0.15s per 100 iterations) without modifying the schema. Note that wrapped existence checks must be isolated using double-select (e.g., `select(select(Model.id).where(...).exists()).scalar_subquery()`) and single columns selected instead of whole objects.
**Action:** When auditing view-layer composition methods that compute counts or statuses for "ready state" widgets or navigation badges, look to consolidate independent `db.query().count()` and `db.query().exists()` calls into a single query via `scalar_subquery()`. Keep python-side validation checks strictly python-side (e.g. validating dictionary presence of `get("full_name")`) rather than trying to construct un-portable json SQL queries.
