## 2024-04-03 - O(2N) -> O(N) score caching for downstream use
**Learning:** During filtering or selection operations in python, avoid running heavy functions (e.g., `_score_profile_item` which aggregates and formats many object properties) multiple times. While Python's `sorted(key=lambda)` calculates the key function only O(N) times (not O(N log N) as mistakenly assumed earlier), recalculating that same key again downstream (like in a list comprehension right after the sort) results in redundant 2*O(N) operations.
**Action:** Pre-calculate complex weights or scores and store them in a tuple along with the items (e.g. `[(idx, item, score)]`) before sorting, allowing you to use that score downstream without recalculation, reducing the overhead to strictly O(N) computations.
