## 2024-05-18 - N+1 Query in Application Serialization
**Learning:** List endpoints utilizing `_serialize_[entity]` helpers (e.g., `_serialize_application`) intrinsically trigger N+1 database queries. When caching attributes (e.g. `latest_run_id`), verify the object has the property (using `hasattr` or `getattr` with a default) rather than assuming it based on database schema conventions to avoid AttributeErrors.
**Action:** Add an optional `cache: dict | None = None` parameter to the helper, pre-fetch relationships using `.in_()` on the collected IDs in the route, and pass the mapped dictionary into the serialization loop. Explicitly seed the cache dictionary with `None` values for all expected IDs to prevent fallback SQL queries when relations are non-existent. Always use `getattr` when dynamically inspecting attributes.
