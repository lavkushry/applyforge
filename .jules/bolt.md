## 2024-10-31 - Consolidate Multiple Dashboard Queries
**Learning:** In dashboard-style endpoints (like `wizard_summary`), executing multiple separate `db.query(...).count()` or `db.query(...).first()` calls creates significant N+1-like latency due to database round-trips. SQLAlchemy's `scalar_subquery()` correctly extracts JSON properties, arrays, exist checks, and counts into a single select object, bringing 6 queries down to 1 query and decreasing processing time by ~50%. Note: `exists()` clauses must be wrapped in a secondary `select()` to avoid AttributeError when converted to `scalar_subquery`.
**Action:** When building dashboard or summary views requiring disconnected counts and entity existence checks, proactively consolidate them into a single `db.execute(select(...))` round-trip rather than loading ORM models individually.
