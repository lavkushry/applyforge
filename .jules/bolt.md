## 2025-02-18 - Optimize Dashboard Endpoints by Consolidating DB Queries
**Learning:** For dashboard-style endpoints like `wizard_summary` that perform multiple independent aggregations (counts and exist checks) on the same user, running individual `db.query(...).count()` or `db.query(...).first()` calls creates an N+1 style inefficiency with sequential DB round-trips. SQLAlchemy's `scalar_subquery()` allows combining all these independent scalar queries into a single master `select()` statement.
**Action:** When implementing dashboard or summary endpoints, always look for opportunities to bundle independent `count()` and `exists()` operations into a single query using `select(...scalar_subquery().label(...), ...)` to drastically reduce database round-trips. Note: `exists()` clauses should be wrapped in an outer `select` before calling `.scalar_subquery()` to avoid `AttributeError: 'Exists' object has no attribute 'scalar_subquery'`.
