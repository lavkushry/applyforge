## 2024-05-15 - Resolving N+1 issues in List Endpoints with dict caching and explicit seeding
**Learning:** In `apps/api`, list endpoints that map over helpers like `_serialize_role` or `_serialize_application` inherently trigger N+1 database queries due to localized relationship fetching. The standardized approach in this codebase is to add an optional `cache: dict | None = None` parameter to the helper, execute a single `.in_()` pre-fetch query in the parent list route, map the results into a dict, and strictly seed the cache with empty defaults (like `None` or `[]`) for all collected IDs to prevent fallback SQL query execution for relations that do not exist.
**Action:** When optimizing N+1 patterns in `_serialize_[entity]` list endpoints, always implement dict pre-fetching and explicitly seed the cache with empty values for every entity ID to guarantee the database fallback block inside the helper function is bypassed.
