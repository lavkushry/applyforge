## 2025-01-20 - Consolidate Multiple Dashboard Queries via Scalar Subqueries
**Learning:** To optimize dashboard-style endpoints in apps/api (e.g., `wizard_summary`), executing multiple independent `func.count()` and `exists()` clauses causes an N+1 database round-trip performance bottleneck. However, pushing complex Python-side validation logic (e.g., checking dictionary keys or array lengths) into the database layer using dialect-specific SQL functions like `func.json_array_length()` can cause instant query crashes in PostgreSQL with JSONB columns.
**Action:** Consolidate multiple independent counts and existence checks into a single database round-trip by wrapping `func.count()` and `exists()` clauses in `scalar_subquery()` calls within a unified SQLAlchemy `select()` statement. When replacing `.first()` queries with subqueries, append `.limit(1)`. Split multiple columns (like `basics` and `skills`) into separate scalar subqueries to prevent multiple row errors. Keep lightweight JSON validation safely on the Python side.
