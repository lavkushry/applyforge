## 2024-05-05 - Optimize SQLAlchemy Sequential Queries
**Learning:** In SQLAlchemy, sequential `query(...).first()` and `query(...).count()` calls for building summary dashboards inherently trigger the N+1 problem. Relying on basic Python boolean evaluation on database results works efficiently, but can be scaled natively down to exactly one query string executing on the backend.
**Action:** When creating or optimizing endpoints returning multiple counts or `exists()` checks (e.g. `wizard_summary`), wrap these lookups in `scalar_subquery()` and execute them as one unified `select()`. Using simple python boolean short-circuits (`row.profile_basics and row.profile_basics.get('full_name')`) provides safety when evaluating the database payload in memory without multiple round trips.
